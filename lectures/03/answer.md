# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：コード上では、エージェントは用語集や講義要点を参照できる。今回は実APIによる回答比較は未実施であり、回答精度が改善したとは主張しない。
- ツール呼び出し：TestModel(seed=3) で `save_learning_log({'lecture': 3, 'content': 'd'})` を発生させ、承認待ち・承認後の再開・ファイル1件の生成を実際に確認した。`d` はテストモデルが生成した模擬内容であり、実際の学習記録ではない。
- 呼び出し回数：保存ツールの呼び出しは1回。再開後の `print_trace` に表示された usage は requests=1 / tool_calls=1。この表示を実API利用回数とは扱わない。
- 追加したツール：`make_quiz(lecture)`。指定回の用語を選び問題と定義をJSONで返す。docstringには復習・理解確認を求められたときに使うと記載した。存在しない回は例外にせず案内を返す。`--list-tools` で合計4ツールの登録も確認した。

## 宿題

- 取り組んだレベル：実装
- やったこと：`save_learning_log(lecture, content)` を追加し、`requires_approval=True` で登録。エージェントの出力型に `DeferredToolRequests` を含め、CLIで保存対象の引数を表示してから承認結果を `DeferredToolResults` に渡し、同じメッセージ履歴で再開するようにした。
- 保存形式：リポジトリ直下の `learning_log/` に講義回・内容・UTC時刻をJSONとして保存。ファイル名はUUIDで自動生成し、排他的作成で既存記録を上書きしない。パスをモデルから受け取らない。既存 `.gitignore` の対象なので個人の記録はコミットしない。
- 結果：Python 3.12.14、固定依存（`uv sync --frozen`、Pydantic AI 2.57.0）で `uv run pytest -q` を実行し **20 passed**。承認待ちは書込みなし、承認時のみ保存、拒否・空入力・EOFでは保存しないことを確認した。明示的な `y` のみ承認する。不正な講義回・空の内容・上限超過も保存しない。複数記録が別ファイルになること、クイズの正常系・存在しない回も確認した。
- 気づき・疑問：プロンプトに確認するよう書くだけではなく、ツール実行の前でハーネスが止める必要がある。承認後は履歴を引き継がないと、保存要求とその承認の対応が失われる。既存の基本ツールテストは基本2ツールを明示して呼ぶようにし、新しい書込みツールの承認・拒否は別テストで検証した。

## 実行範囲と再現方法

- AI支援を利用して実装・テストした。実行環境はローカルLinuxで、Codespacesは起動していない。
- 実装課題で指定されたTestModelによる動作検証を実施した。Gemini等の実APIは利用しておらず、モデルによる自然言語解釈・回答品質やレート制限の評価は未実施。
- `uv sync --frozen` → `uv run pytest -q` で再現できる。
- `uv run python -m app.agent --list-tools` はAPIキーなしで実行可能。
- 実API利用時は通常どおり環境変数にキーを設定し、`uv run python -m app.agent --trace "第3回で学んだ、承認後のみ保存するという内容を学習記録に保存して"` を実行する。表示された引数を確認し、`y` で承認、それ以外で拒否する。キーはコード・解答・ログに記載しない。
- 承認制御の参考：Pydantic AI公式 Deferred Tools（https://pydantic.dev/docs/ai/tools-toolsets/deferred-tools/）。実装は配布リポジトリの固定版で動作確認した。
